# i18n — Internationalisation multilingue Antaios

**Date** : 2026-07-12  
**Statut** : Design validé, prêt pour implémentation

---

## Direction linguistique

- **Langue par défaut** : anglais (`en`)
- **Langue secondaire** : français (`fr`)
- **Architecture extensible** pour espagnol (`es`), allemand (`de`) plus tard
- Les données extraites (commodities, noms de produits, certifications) sont dans la langue des documents source — la traduction se fait **à l'affichage**

---

## Détection de la langue — 3 couches

```
getUserLocale()
├── 1. User override explicite → localStorage "antaios:locale" + Convex user.locale
├── 2. Browser : navigator.language / navigator.languages
├── 3. OS : Intl.DateTimeFormat().resolvedOptions().locale
└── Fallback → "en"
```

Exécuté au boot de l'app dans le provider racine (`app.tsx`). Le changement de langue est persistant via localStorage + Convex.

---

## Stack technique

| Technologie | Usage |
|---|---|
| `react-i18next` + `i18next` | Framework i18n standard pour React |
| `i18next-browser-languagedetector` | Détection automatique navigateur/OS |
| Fichiers `src/locales/{lang}.json` | Traductions statiques |
| Convex `translationCache` table | Cache partagé des traductions de données dynamiques |
| DeepL API (`convex/lib/translate.ts`) | Traduction des données non trouvées en cache |
| Table de lookup locale | Traductions naturelles pour commodities EUDR courantes |

## Architecture

### 1. Traductions statiques (react-i18next)

Fichiers dans `src/locales/` :

- `en.json` — langue source (toute l'UI en anglais)
- `fr.json` — français
- (futur) `es.json`, `de.json`

Structure :
```json
{
  "status": {
    "draft": "Draft",
    "extracting": "Extracting",
    "resolving": "Reviewing"
  },
  "shipment": {
    "create": "New shipment",
    "empty": "No shipments yet"
  },
  "conflict": {
    "title": "Resolve conflicts",
    "send_to_supplier": "Send to supplier"
  },
  "fields": {
    "commodityName": "Commodity",
    "supplierName": "Supplier name"
  }
}
```

Tout le texte UI statique actuellement en français est :
1. Extrait vers `fr.json` (tel quel)
2. Traduit en anglais pour `en.json`
3. Remplacé dans les composants par `t('clef')`

### 2. Traductions dynamiques — commodities et données extraites

**Problème** : open set infini de noms de produits, impossible d'avoir une clé i18n pour chaque.

**Pipeline `useTranslatedValue(value, targetLang)`** :

```
┌─────────────────────────────────────────────────┐
│  useTranslatedValue("Raw Cocoa Beans", "fr")    │
├─────────────────────────────────────────────────┤
│  1. Lookup table locale → "Fèves de cacao"  ✅  │
│     (return immédiat, pas d'appel réseau)        │
├─────────────────────────────────────────────────┤
│  2. Cache Convex (query) → hit              ✅  │
│     (return, partagé entre utilisateurs)         │
├─────────────────────────────────────────────────┤
│  3. DeepL API via mutation Convex                │
│     → store dans translationCache                │
│     → return traduction                          │
└─────────────────────────────────────────────────┘
```

**Lookup table** : `src/lib/commodity-translations.ts`

```ts
const COMMODITY_TRANSLATIONS: Record<string, Record<string, string>> = {
  "Raw Cocoa Beans": { fr: "Fèves de cacao" },
  "Cocoa Beans": { fr: "Fèves de cacao" },
  "Robusta Coffee": { fr: "Café Robusta" },
  "Arabica Coffee": { fr: "Café Arabica" },
  "Palm Oil": { fr: "Huile de palme" },
}
```

Couverture : ~50 entrées EUDR courantes (cacao, café, huile de palme, soja, caoutchouc, bois, bœuf, etc.) + leurs variantes en anglais/français.

**Table Convex `translationCache`** :

```ts
// convex/schema.ts
translationCache: defineTable({
  sourceText: v.string(),
  sourceLang: v.string(),
  targetLang: v.string(),
  translatedText: v.string(),
  createdAt: v.number(),
})
  .index("by_source_target", ["sourceText", "sourceLang", "targetLang"])
```

Clé unique : `sourceText + sourceLang + targetLang`. Cache partagé entre tous les utilisateurs.

### 3. Traduction des questions de résolution de conflit

Les questions sont déjà générées en français par `convex/merge.ts`. Deux cas :

- **Affichage en français** : pas de changement, on affiche tel quel
- **Affichage dans une autre langue** : passage dans le pipeline `useTranslatedValue` avec `sourceLang: "fr"` → cache → DeepL

### 4. Sélecteur de langue dans le header

Petit dropdown dans `-ui.navigation.tsx` à côté du menu utilisateur avec :

- 🇬🇧 English
- 🇫🇷 Français
- (futur) 🇪🇸 Español

Au changement :
```ts
setLocale(lang)           // → localStorage
updateUserLocale(lang)    // → Convex mutation
i18next.changeLanguage(lang)  // → react-i18next
```

### 5. Migration des composants existants

Le texte français actuel est conservé dans `fr.json`. Les composants sont migrés pour utiliser `t()`.

Pas de traduction automatique — chaque string est déplacée manuellement vers les fichiers JSON.

## Ce qui n'est PAS traduit

- Données géospatiales (coordonnées, GeoJSON)
- Nombres et dates (déjà formatés via `Intl` avec le bon locale)
- Noms de fichiers uploadés
- Contenu des emails fournisseurs (déjà géré par DeepL existant dans `convex/supplier_email.ts`)
- Messages d'erreur techniques (console, logs)

## Détection de la langue au boot

```ts
// app.tsx — useInitializeLocale hook
function useInitializeLocale() {
  useEffect(() => {
    const stored = localStorage.getItem("antaios:locale")
    if (stored && ["en", "fr"].includes(stored)) {
      i18next.changeLanguage(stored)
      return
    }

    const browserLang = navigator.language?.split("-")[0]
    if (browserLang && ["en", "fr"].includes(browserLang)) {
      i18next.changeLanguage(browserLang)
      return
    }

    const osLang = Intl.DateTimeFormat().resolvedOptions().locale?.split("-")[0]
    if (osLang && ["en", "fr"].includes(osLang)) {
      i18next.changeLanguage(osLang)
      return
    }

    i18next.changeLanguage("en") // fallback
  }, [])
}
```

## État existant vs. état cible

| Avant | Après |
|---|---|
| "Brouillon" en dur dans le code | `t("status.draft")` avec clé dans `en.json` et `fr.json` |
| "Raw Cocoa Beans" affiché tel quel | Lookup table → "Fèves de cacao" (fr), fallback DeepL |
| Français hardcodé partout | Détection auto EN/FR, sélecteur header |
| Pas de i18n | react-i18next + cache Convex + DeepL |
| 1 langue (français) | Infrastructure pour N langues |
